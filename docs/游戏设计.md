# 小游戏设计 · 清场

工作名：《清场》。第三人称、单人、一局打完。

## 使用条件

- UE 5.8.4
- 大课，讲台演示，学生不跟做

## 一句话

一个小场地里刷 5 个小怪，它们直线追着你打；你用准星点射清完就赢，血量归零就输，按 R 重开。

## 核心循环

进关 → 移动 / 跳跃 / 瞄准 → 点射小怪 → 被打掉血 → 清完或倒下 → 重开

## 一局怎么走

- 开局：GameMode 在 5 个刷怪点各生成 1 个小怪，HUD 显示 100 血、剩余 5
- 过程：小怪朝玩家直线移动，进入 200 cm 后每 1.5 秒打一下，每下 10 血
- 玩家：射线命中一次 25 伤害，小怪 50 血，两枪一个
- 胜利：剩余 0，屏幕显示「清场完成」
- 失败：玩家血量 0，显示「你倒下了」
- 重开：按 R，重置关卡

## 数值

| 项 | 值 |
| --- | --- |
| 玩家血量 | 100 |
| 玩家单发伤害 | 25 |
| 小怪血量 | 50 |
| 小怪伤害 | 10 / 次 |
| 小怪攻击间隔 | 1.5 s |

| 小怪移动速度 | 300 |

数值只是起点，手感不对就调。

## 关卡

- 一块 3000 × 3000 cm 的封闭场地，墙高 400
- 地面 + 四面墙 + 5 个箱子当掩体
- 1 个 PlayerStart，5 个 TargetPoint 当刷怪点，分散在场地四周
- 一盏定向光 + 天空光，够看清就行
- 不做导航网格、不做门、不做多层

## 动画

玩家状态机（AnimBP）：

| 状态 | 进入条件 | 动画 |
| --- | --- | --- |
| Idle | 速度 ≈ 0，在地面 | 待机 |
| Run | 速度 > 0，在地面 | 跑步，按速度混合 |
| Jump | IsInAir 且 Z 速度 > 0 | 起跳 |
| Fall | IsInAir 且 Z 速度 ≤ 0 | 下落 |
| Dead | IsDead | 死亡 |

- 射击用 Montage 叠在上半身，不单独做状态
- 受击可选：播一个短暂受击 Montage，不做硬直
- 小怪只有 Idle / Run / Attack / Dead 四态
- 驱动变量就四个：`Speed`、`IsInAir`、`IsAttacking`、`IsDead`
- 讲法：状态机管「持续状态」，Montage 管「一次性动作」

## 血量

- `UHealthComponent`，玩家和小怪各挂一个
- 字段：`MaxHealth`、`CurrentHealth`
- BeginPlay 绑定 Owner 的 `OnTakeAnyDamage`
- 扣血后广播 `OnHealthChanged(Current, Max)`；归零再广播 `OnDied`
- 伤害统一走 `UGameplayStatics::ApplyDamage`，不直接改别人的血量
- 好处：玩家和小怪共用一套，HUD 只认委托

## HUD

- `WBP_HUD`：血条、剩余敌人数、准星、胜负提示
- 血条监听 `OnHealthChanged`，剩余人数监听 GameState 的委托
- 不在 Tick 里轮询血量
- 由 PlayerController 在 BeginPlay 创建并加到视口

## 射线

- 开火时取准星在屏幕上的位置，`DeprojectScreenPositionToWorld` 得到世界起点和方向
- 从摄像机位置沿方向打 `LineTraceByChannel`，距离 5000
- `AddIgnoredActor(this)` 忽略自己
- 命中目标若挂 HealthComponent，就 `ApplyDamage`
- 可选：从枪口再画一条调试线，确认打的点和看到的一致

## 现场 AI 开发任务

四个任务，每个 6 分钟：现场写提示词 → 生成 → 审查 → 编译 → 验收 → 提交。

下面的提示词只用来对照验收，不是照读稿。现场先看基础工程里哪个类是空的、哪个方法还没写，再决定提示词怎么落。

提示词可以口语化，甚至乍看很粗糙，但程序逻辑和架构判断要在里面：

- 数据放哪：血量归组件，剩余人数归 GameState，规则归 GameMode，不混层
- 谁触发：伤害走 `ApplyDamage` / `OnTakeAnyDamage`，不另开一条旁路
- 谁通知谁：组件广播、HUD 订阅，不让表现层反查规则层
- 改动边界：先定接口，再写实现，只碰该碰的类
- 验收标准：能编译、运行看得见、diff 没越界

写提示词的过程本身就是要讲的内容：句子可以不漂亮，层次不能乱。

### 任务 1 · 血量组件

```text
在 ClearArena 项目里实现 UHealthComponent：
- MaxHealth 默认 100，CurrentHealth 初始等于 MaxHealth，可在蓝图里改
- BeginPlay 绑定 Owner 的 OnTakeAnyDamage
- 受伤后扣 CurrentHealth，广播 OnHealthChanged(Current, Max)
- 归零广播 OnDied，只触发一次

```

- 审查：委托签名、绑定时机、死亡重复触发、空指针
- 验收：日志能看到扣血，后续 HUD 能接上
- 提交：`step1-health`

### 任务 2 · 射击与射线

```text
在 AClearArenaCharacter::Fire 里实现第三人称点射：
- 取屏幕中心（准星）位置，DeprojectScreenPositionToWorld 得到世界起点和方向
- 从相机位置沿方向做 LineTraceByChannel，通道 Visibility，距离 5000
- AddIgnoredActor(this)，不要打到自己
- 命中 Actor 如果挂了 UHealthComponent，调用 UGameplayStatics::ApplyDamage，伤害 25

```

- 审查：通道、忽略自己、伤害是否走 `ApplyDamage`、命中空指针
- 验收：准星指哪打哪，小怪两枪倒，不误伤自己
- 提交：`step2-fire`

### 任务 3 · 敌人

```text
实现 AClearArenaEnemy：
- Tick 里朝玩家移动，速度 300，乘 DeltaTime
- 距离 200 内，每 1.5 秒对玩家 ApplyDamage 10
- 自己血量归零时通知 GameMode，然后销毁
- 不用导航、行为树、AIController
- 玩家为空时站着不动

```

- 审查：Tick 开销、DeltaTime、冷却、死亡只触发一次、空指针
- 验收：小怪会追、近身会打、被打死会消失
- 提交：`step3-enemy`

### 任务 4 · 胜负与 HUD

```text
实现 AClearArenaGameMode、AClearArenaGameState 和 HUD 绑定：
- GameMode 开局在场景 5 个 TargetPoint 处各生成 1 个 Enemy，并记录剩余数
- 敌人死亡时剩余数减 1，减到 0 判胜
- 玩家 OnDied 时判负
- GameState 保存 RemainingEnemies 和 bGameOver，并提供变更委托
- HUD 绑定血条、剩余数、胜负提示；按 R 重开
- 单人，不做网络同步
```

- 审查：计数不重复扣、胜负只触发一次、委托绑定与解绑、重开方式
- 验收：清完 5 个显示胜利，血量归零显示失败，R 能重开
- 提交：`step4-win`

## 零 C++ 的讲法

课上一行新代码都不手写，目标只有一个：看到源码能指认。

- AI 生成后先看 diff，再读函数：这段属于谁、什么时候跑、改了什么
- 头文件当目录，cpp 当正文：先看类里有什么，再看函数怎么做
- 只认三个宏：`UCLASS`、`UPROPERTY`、`UFUNCTION`
- 指针当遥控器：它指向一个对象，不是对象本身
- 读一条链路就够：开火 → 射线 → `ApplyDamage` → 血量组件 → 委托 → HUD
- 手工只改数值和日志：伤害 25 → 50、血量 100 → 200、加一行打印，然后重新编译
- 不展开模板、智能指针、内存管理，只说明「对象由引擎回收」
