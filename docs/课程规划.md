## 这节课讲五块

### 1. 认识基本界面

先让人能在编辑器里找到东西、点得动、看得懂。

- 打开工程，分清视口、内容浏览器、大纲（Outliner）、细节（Details）
- 在关卡里点选、移动 Actor，看细节面板跟着变
- 玩一次：Play / PIE，停下来回到编辑
- 知道「现在改的是关卡里的这个东西」，先不展开蓝图和 C++

### 2. 游戏开发必备知识

只讲这局游戏真的会用到的几件，讲完立刻在编辑器里验证。

#### 2.1 坐标系

- UE 是左手系：X 向前、Y 向右、Z 向上，和数学课上常见的 Y 朝上不一样
- 位置、旋转、缩放分别对应 Location / Rotation / Scale
- Rotation 三个轴：Pitch 抬头低头、Yaw 左右转、Roll 侧翻；用手腕动作演示最直观
- 世界坐标和局部坐标的区别：Actor 自带的箭头是它的前方向，挂到父物体上之后会跟着转
- 单位是厘米：默认角色身高约 180，一格地板 100，建立尺度感
- 动手：在关卡里摆三个物体，分别沿 X / Y / Z 移动，再用旋转看清 Pitch / Yaw / Roll

#### 2.2 射线检测

- 一句话：从一个点朝一个方向发一条线，问「打到了什么」
- 两个输入（起点、方向）和一个输出（命中结果：打中了谁、打在哪、离多远、法线朝哪）
- 线检测（Line Trace）和球形检测（Sphere Trace）的区别：一个点扫、一个有粗细
- 通道（Trace Channel）先只讲 Visibility 和 Camera，知道「只测该测的东西」
- 碰撞预设只带一句：Block / Overlap / Ignore，知道射线会被什么挡住
- 在这局游戏里的用途：准星打靶、拾取、判断脚下有没有地面，挑一个作为演示
- 动手：鼠标点哪打哪，打印出命中的 Actor 名字和距离

#### 2.3 游戏循环与 Tick

- 引擎每帧做一轮：处理输入、更新世界、渲染。游戏逻辑大多挂在这轮的某个点上
- Tick 是「每帧都跑」，输入回调和碰撞是「发生了才跑」；先分清这两类
- DeltaTime：这一帧花了多久。乘上它，速度才是每秒多少，而不是每帧多少
- 帧率高低不该改变游戏速度；用 DeltaTime 做一次「每秒移动 200」的验证
- 动手：让物体每帧前进，分别用「每帧固定距离」和「乘 DeltaTime」，对比不同帧率下的结果

### 3. 用面向对象速通 Gameplay 框架

用这局游戏里的角色来讲，不单独开一章 OOP。

- 类和对象：类型是图纸，关卡里放进去的是对象
- Actor 是能放进关卡的东西；组件挂在 Actor 上，负责某一块能力
- 继承关系只过这条主线：GameMode、Pawn / Character、Controller、PlayerState、GameState
- 每个类只回答一个问题：谁定规则、谁是被控制的角色、谁在发输入、谁记分、这一局现在什么状态
- 讲完要能在这局游戏里对上号，不背全框架

#### 我的代码什么时候跑

- BeginPlay：这个对象进入游戏时跑一次，做初始化
- Tick：每帧跑，适合持续变化的东西；能在事件里做就不要放 Tick
- 输入回调：玩家按键时才跑，不按就没有
- EndPlay：对象离开游戏时跑一次，做收尾
- 一句话记住：初始化在 BeginPlay，持续变化在 Tick，响应在回调，收尾在 EndPlay

### 4. 蓝图与 C++：读源码前的地基

同一个类可以用蓝图写，也可以用 C++ 写；读源码前先把这层关系讲通。

- 蓝图和 C++ 是同一个类的两种写法，不是两套系统
- 看一眼蓝图节点，再看它对应的 C++ 类，建立「这两个是一回事」的直觉
- UCLASS / UPROPERTY / UFUNCTION：告诉引擎「这个类、这个变量、这个函数要认识」
- GENERATED_BODY() 和 U 前缀：引擎的反射与对象管理需要它们，不是装饰
- GC：UObject 由引擎管生命周期，普通 C++ 对象不是；谁持有、谁会被回收
- C++ 最低限度：头文件写声明、cpp 写实现；指针是地址不是对象；TObjectPtr 是什么
- 学生不会 C++：不要求写，只要求指认；语法能省就省

#### 零基础只认这几个锚点

- 头文件看「这个类有什么」，cpp 看「具体怎么做」
- 只认三样：类名、`UPROPERTY` 变量、`UFUNCTION` 函数
- 函数体先找 `BeginPlay` / `Tick` / 输入，知道它什么时候跑
- 指针理解成遥控器：指着一个对象，不是对象本身
- 课上只改数值和一行日志，不写新函数

### 5. 现场 AI Native 开发，并一起读 C++ 源码

基础工程课前准备好，课上只做增量：用 AI 生成关键逻辑，老师审查、编译、演示，再一起读生成的代码。

预置到什么程度：

- 工程、关卡、光照、刷怪点、PlayerStart
- 角色移动、相机、Enhanced Input（开火键已绑，`Fire()` 里只有一行日志）
- Idle / Run / Jump / Fall 动画状态机
- HUD 布局摆好，血条和人数还没绑定
- 血量、敌人、GameMode、GameState、HUD 的类和骨架都在，方法留空

现场做四个任务，每个 5–6 分钟：

1. 血量组件：扣血、广播、死亡
2. 点射：准星 → 射线 → ApplyDamage
3. 敌人：追人、攻击、死亡
4. 胜负与 HUD：刷怪、计数、结算、重开

#### AI Native 怎么走

1. 说清需求：目标、改哪个文件、不许动什么、验收标准
2. 生成后先看 diff：改了哪些文件，有没有越界
3. 编译，运行，按验收标准试一遍
4. 通过就提交；不通过把报错原样喂回去
5. 老师只讲两件事：这段为什么这么写，哪里不能信 AI

#### 必须人工审查的点

- 射线有没有忽略自己、通道对不对
- 伤害是不是走 `ApplyDamage`
- 委托有没有重复绑定、死亡会不会触发两次
- Tick 里有没有不必要的开销
- AI 编造的 API：编译不过就是它，正好讲怎么读报错

#### 改完代码为什么不生效

- 改 C++ 要编译；Live Coding 能热更一部分改动，改类结构、加成员变量往往要重启编辑器
- 遇到「代码明明改了却没反应」，先确认编译过没有，再确认跑的是不是最新模块
- 演示：故意改一行打印，走一遍「改 → 编译 → 看到输出」的完整链路
