## 这节课要干什么

不教语法，不给代码，只给一张地图：**学什么、为什么学、什么时候学、按什么顺序学、怎么判断自己学到了**。

- 一句话：听完能给自己排一条半年的学习路线，而不是记住几个名词。
- 听众：会用蓝图、想往 C++ 走的人；零 C++ 基础也能听。
- 形式：大课，讲台演示，不跟做；一页一个观点，讲解放口头。
- 时长：105 分钟（12 段预算之和）。标 ★ 的必讲，砍到 60 分钟也能讲完。
- 与第一节课的关系：第一节课讲「一局游戏怎么跑起来」，导向课讲「你接下来怎么走」。可放在系列最前，也可放在第一节课之后——前者是发地图，后者是回望。

## 不做什么

- 不出现大钊的知乎 / B站 / QQ 群 / 邮箱等联系方式
- 不把 UE4 时代的旧写法当成唯一答案（`BindAxis`、Hot Reload、VS + Visual Assist），但也不假装旧项目里没有它
- 不堆 API 清单：只讲「有这一块」，细节留给实践
- 页上只留关键词和一张图，讲者在备注里展开

## D What：什么是虚幻 C++

| 页 | 标题 | 页面内容 | 讲解要点 |
| --- | --- | --- | --- |
| P12 ★ | 旧教程还能照抄吗 | 副标题：地图没变，路修过。六行对照，左旧右新：输入 `BindAxis` → **Enhanced Input**（`UInputAction` + `IMC`）；裸指针 `UPROPERTY` 成员 → **`TObjectPtr<>`**；到处写 Manager / 塞 GameInstance → **`USubsystem` 家族**；`FVector` 是 float → **LWC，`FVector` 默认 double**；官方第一人称模板当范本 → **Lyra + Game Features**；Hot Reload、VS + Visual Assist → **Live Coding、Rider**。脚注：StateTree / MetaSounds / Chaos、World Partition 是同类替换，认识名字即可。 | 这页是给学生「解雷」的：网上一半教程是 UE4 的，照抄会编译不过，或者写出今天不该有的结构。落点——**看到旧教程不用慌，先认出它用的是哪套**；课上一律按 5.8 的写法讲，但不假装旧写法不存在。 |
| P13 ★ | 虚幻 C++ ≠ C++ | 六块拼图：**标准 C++ 底子 / 引擎的 C++ 框架 / 模块与插件配置（UBT）/ 反射与代码生成（UHT）/ Core 的库（`FString`、`TArray`、`UE_LOG`）/ 与蓝图交互**。 | 关键一句：C++ 只是地基，剩下五块是「引擎的规矩」。很多人学不下去，是只学了第一块。右侧小字：UE5 这些年加的 `Subsystem`、Enhanced Input、StateTree，不是第七块，是这六块在应用层的新补丁。 |
| P14 ★ | 学会的四条标志 | 四条竖排：① 能看懂编译与链接错误（多半是模块配置）；② 认得常见套路（`CreateDefaultSubobject`、`UPROPERTY`）；③ 理解 UObject 的内存管理，不天天崩；④ 能在源码里定位到自己要的那段。 | 反过来当自测表：四条一条都没有，说明还没入门，不是笨。 |
| P15 | 它不是什么 | 三条误区，各配一个叉：不是「背完 C++ 语法」；不是「以后只写 C++」；不是「记住几千个 API」。 | 提前拆掉心里的门槛。API 记不住很正常，找得到就行。 |

| P29 ★ | Module · 依赖怎么连 | `Build.cs`（`ModuleRules`）三组：`PublicDependencyModuleNames` / `PrivateDependencyModuleNames` / `DynamicallyLoadedModuleNames`。口诀：**public 会传染，private 不外传**。 | 讲一个真实报错：`undefined symbol` 十有八九是少加一个模块名。 |
| P30 | Module · 头文件与包含 | 两列：`PublicIncludePaths` / `PrivateIncludePaths`（默认就是 `Public`、`Classes` 与 `Private`）；`PublicIncludePathModuleNames` / `PrivateIncludePathModuleNames`（只包含头文件、不链接）。中间一张「谁能看见谁」的圈图。 | 这页最容易讲糊。配圈图，不要念定义。 |
| P31 | Module · 第三方库、宏、平台 | 三行：`PublicAdditionalLibraries` / `PublicSystemLibraryPaths` / `PublicDelayLoadDLLs`；`PublicDefinitions` / `PrivateDefinitions`；`Target` 给出 `Platform`（Win64 / Android / iOS）与 `Configuration`（Debug / Development / Shipping）。 | 一页带过，告诉学生「接第三方库时回来翻这页」。 |
| P32 ★ | 反射 · UHT 生成了什么 | 左：源码 `UCLASS()` + `#include "X.generated.h"`；右：反射代码；中间箭头标 UHT。下方：`MODULENAME_API` 是什么、漏写会怎样。七个符号一字排开：`UCLASS` `USTRUCT` `UENUM` `UPROPERTY` `UFUNCTION` `UINTERFACE` + `GENERATED_BODY()`。 | 一句话：宏不是注释，是给另一个程序看的输入。 |
| P33 | 反射 · 运行时能干什么 | 五个类型对象：`UClass*` `UScriptStruct*` `UFunction*` `FProperty*` `UField*`。两件事：遍历属性读 / 写；遍历函数并调用。底部大字：**对象用类型描述，类型本身也是对象**。区分 Class Reference 与 Object Reference。 | 举实际用途：编辑器工具、通用存档、数据校验。 |
| P34 ★ | GC · 谁能被回收 | 一张引用链图：根 → 对象 → 成员。红字：**只有 `UPROPERTY` 标记的引用才进 GC 分析**。补充：非 UObject 结构体与 UObject 混用要小心 `FGCObject::AddReferencedObjects`。UE5 两条：成员写 **`TObjectPtr<T>`** 而不是裸指针，增量 GC 下才安全；判空用 `IsValid()`，`!= nullptr` 骗得过编译骗不过 GC。收尾：**自从用了 UE，就再也不用 new / delete 了**。 | 最常踩的坑：裸指针存对象，看着好好的，某天突然变空。 |
| P35 | CDO 与 Package | 左：CDO——每个类有一个默认对象，蓝图里看到的默认值就是它（`UClass::GetDefaultObject`），序列化以它为模板。右：Package——对象用包组织，包可以互相引用，按路径找对象。 | 一页带过。作用是解释「为什么改了默认值，新生成的对象就变了」。 |
| P36 ★ | 套路清单 | 六格：UHT 宏 / 模块链接（`AddRange`）/ Actor 创建（`CreateDefaultSubobject` + `TObjectPtr` 成员、`SetupAttachment`；`ConstructorHelpers` 只用在构造期，运行期加载走 **Asset Manager + 软引用**）/ Gameplay 继承（GI、GM、GS、PC、Pawn、PS 一波带走）/ C++ 与蓝图交互（`UPROPERTY`、`UFUNCTION`、函数库）/ **Enhanced Input**（`UInputAction` + `UInputMappingContext` + `BindAction`）、委托与 `FTimerManager`。 | 「套路」是最实用的词：会写套路，就写得像引擎。强调别在关卡蓝图里堆逻辑。特别提醒：别再教 `BindAxis`，那是老输入系统，5.x 模板已全换 Enhanced Input。 |
| P37 | 常用库 | 三张卡：`GameplayStatics`（拿 Gameplay 对象、生成、伤害）/ `KismetSystemLibrary`（系统功能、`LineTrace`）/ `KismetMathLibrary`（数学）。 | 提醒：这些是「不知道怎么写时先翻的地方」，不是要背。 |

## K 核心概念与源码剖析

| 页 | 标题 | 页面内容 | 讲解要点 |

| P46 ★ | 一切从 GEngine 开始 | 两行代码：`UEngine* GEngine`（`UGameEngine` / `UEditorEngine`）、`UEditorEngine* GEditor`。左右各三条能拿到什么。GEngine → Worlds、游戏视口；GEditor → 当前选中、当前视口、编辑器功能、事件回调。底部大字：**编辑器也是个游戏，只是一堆 UObject**。 | 这页最容易被记住，也最容易被神化。落点：拿到对象就能做事，而对象都能拿到（`NewObject`、对象池、运行时加组件）。 |
| P47 | 源码怎么剖析 | 两张方法论卡：**时空观**（时：调用顺序与触发时机；空：数据怎么流动与变形）；**信息论**（依赖越少越稳定；信息就是能量）。右侧七个问题：一开始有什么 / 谁点的第一把火 / 自循环靠什么推 / 外部输入有哪些 / 吐出了什么 / 最后剩下什么。 | 别讲成哲学课，举一个具体函数走一遍。 |
| P48 | 心法 | 两句：**保持谦逊但不迷信**（97.34% 的情况下是自己的问题；要批评源码，先能写出更好的方案）；**比好奇心更需要耐心**（调用链太长、背景知识不够、无人可问、源码太大）。 | 承认一天只有 24 小时，只够掌握一小块——这不是失败，是常态。 |
| P49 ★ | 找：顺藤摸瓜 | 五个抓手：Widget Reflector 定位控件 / 查找所有引用 / 全局字符串搜索 / Everything 找文件 / 断点看调用栈。一句话：**相信它一定在，只是你还没找到**。 | 现场演示一次：从一个按钮点到它的 C++ 实现。 |
| P50 | 搬：怎么借得干净 | 四条：能直接调就别拷代码；先看目标代码的输入输出与内部依赖；流程上插一脚就去找那个「旋钮」；别在 Runtime 下想办法调 Editor 的代码。 | 「借用」的目标是可维护，不是能跑。 |

## 相对 UE4 原 PPT 的更新点

原 PPT 是 UE4 时代的（C++11、老输入系统、Hot Reload），改成 5.8 讲，逐条记在这里，免得讲的时候嘴瓢。

| 主题 | 原 PPT / UE4 写法 | 课件按 UE5 5.8 写 |
| --- | --- | --- |
| 语言标准 | C++11 / 14 | **C++20**（5.3 起默认，C++17 已弃用） |
| 输入 | `BindAxis` / `BindAction`、Input 设置 | **Enhanced Input**：`UInputAction` + `UInputMappingContext` + `BindAction` |
| 对象指针成员 | 裸指针 + `UPROPERTY()` | **`TObjectPtr<T>`**（增量 GC 下才安全） |
| 全局服务 | Manager 类、往 GameInstance 里塞 | **`USubsystem`** 家族（Engine / Editor / GameInstance / World / LocalPlayer） |
| 坐标与数值 | `FVector` 是 float | **LWC**：`FVector` 默认 double，要单精度用 `FVector3f` |
| 资源引用 | `ConstructorHelpers` 到处用、硬指针 | 构造期才用 `ConstructorHelpers`；运行期走 **Asset Manager + 软引用** |
| 热更 | Hot Reload | **Live Coding**（Ctrl+Alt+F11）；头文件与 `Build.cs` 改动仍需整体重编译 |
| 官方范本 | 第一人称 C++ 模板、ShooterGame | **Lyra**（Game Features / Modular Gameplay）+ 第三人称模板 |
| 编辑器 | VS + Visual Assist | **Rider** 或 VS Code + clangd |
| 新增子系统 | — | **StateTree** 取代部分行为树用法、MetaSounds 取代 Sound Cue、Chaos、World Partition |

只更新写法，不更新结构：六块要点、5W1H、学习闭环和境界阶梯跟引擎版本无关，原封不动。
